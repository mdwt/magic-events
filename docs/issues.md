# Issues

The working list for version 1, as three tables: what is still being worked on, what is noted for phase 2, and what
is closed. One row per issue. A row says what the issue is and what was decided or built. Where a decision changes how
the system works, it is also in the document that owns the subject.

2026-11-23 · Meiring

**Status:** `In progress` being built now · `To do` decided, and starts when the work it waits on is committed ·
`Phase 2` decided or noted, and not part of version 1 · `Closed` decided, and built where it needed building.

| 42 | Jobs that are given up are only in pg-boss's own table | Jobs | A job whose retries are used up is logged as an error and stays in pg-boss's table. A dead letter queue belongs with the move to more durable jobs in version 2 |
| 66 | The MCP server does not speak the specification's newest revision | MCP | The server speaks revision 2025-11-25 and the four before it, which is what Claude connects with today. | 45 | A venue whose listing states no coordinates has no position | Data processing | Decided: no geocoding in version 1. A geocoding service behind a port is for phase 2 |
| 74 | An experience known only from a source that only a browser can read is never checked again | Discovery | The schedule fetches every active source again each week, which is how an experience months away is kept true. Sources that need a logged-in browser or JavaScript are loaded from a browser scrape and saved inactive, so their experiences stay as captured until a new scrape, or until their dates pass. On 23 Nov 2026 that is 28 experiences, from Facebook events and Benguela Cove. Decided: not in version 1 (see [v1-decisions.md](v1-decisions.md)) |
| 50 | A search with a query text waits for the query's embedding | Catalogue | Bedrock takes about 1.3 to 2.0 seconds to embed the query text. After 5 seconds the search ranks by keyword alone. Keeping the embeddings of repeated query texts is for phase 2 |
